## 3. 晚上在顯示卡電腦上要做的事（依序）

1. 照 [move-to-gpu.md](move-to-gpu.md) 安裝、放回 `pipeline\data`、換 CUDA 版 torch，確認 `torch.cuda.is_available()` 是 True。
2. **停用舊電腦的自動接續排程**（Claude 的 `tw-stock-terminal-resume`），同一時間只讓一台電腦發布。
3. 先在 GPU 上量速度：`uv run --no-sync python -m pipeline forecast 2330`（日誌會印出「裝置 cuda」與耗時）。
4. 決定模型（見下一節），再跑回測：`uv run --no-sync python -m pipeline backtest`。
5. 回測完成後：`uv run --no-sync python -m pipeline moves`（可略）→ `export` → `publish`，並如實回報整體命中率，包含表現不好的部分。
6. 試一次 GDELT：`uv run --no-sync python -m pipeline ingest news`；抓到後 `attribution` → `export` → `publish`。

## 4. Kronos 模型：在顯示卡上可以做的事（需要使用者決定）

目前用的是 **Kronos-mini、未針對台股微調**。選 mini 是因為一般 CPU 上 small 慢 5 倍、回測跑不完。換到顯示卡後有三個選項：

| 選項 | 內容 | 代價 | 建議 |
|---|---|---|---|
| A. 維持 mini，只用 GPU 跑完回測 | 接著算剩下的 2,041 次 | 最快；結果與已上線的預測一致 | 至少要做 |
| B. 換成 Kronos-small 或 base | 較大的預訓練模型，可能比較準 | **要重跑全部預測與回測**（新舊模型不能混在一起比較）；GPU 上預計數小時內 | 先在 GPU 上量速度再決定 |
| C. 用台股資料微調（訓練）Kronos | 讓模型學台股的特性 | 工作量最大；**必須只用最早回測基準日之前的資料訓練**，否則回測會偷看答案、命中率失真；要把訓練期間、資料、超參數寫進分析說明 | 等 A 或 B 的回測結果出來，看有沒有優勢再決定 |

不管選哪個，網站「關於 → 分析說明」都會自動記錄實際使用的模型名稱、權重版本、計算時間與資料期間（`export/provenance.py`）。
選 C 的話要另外在 provenance 加一項「微調」的說明（訓練資料期間、驗證方式、超參數），並在 PLAN.md 記錄這個決定。
